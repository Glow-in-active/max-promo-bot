# Проверка проекта

Go-сервис десятидневной промоакции с PostgreSQL и адаптером бота MAX.

## Что сделано

| Функция | Ожидаемое поведение |
| --- | --- |
| Меню | Баннер и пять кнопок |
| Промокоды | Уникальный код с инструкцией; повтор за день возвращает тот же код |
| Подписка и шансы | Регистрация после проверки подписки; код и заявка дают один шанс за день, максимум десять |
| Розыгрыши | Дневные победители, взвешенный финал, сохранённый результат и подтверждение администратора |
| Получение приза | Имя, фамилия и согласие; после срока ответа приз переходит резерву |
| Отчётность | Пользователи, заявки, выдачи, остатки по партнёрам и CSV |

## Запуск

Нужны Docker Compose с поддержкой `--wait` и make. Go и аккаунт MAX не нужны.

```sh
make up
curl --fail http://127.0.0.1:8080/readyz
```

Ожидаемый ответ: `{"status":"ready"}`. Compose собирает приложение, запускает PostgreSQL и выполняет миграции. Файл `.env` для demo не требуется.

## Пройти сценарии

### В браузере

```sh
make simulator
```

Откройте [127.0.0.1:4010](http://127.0.0.1:4010/), создайте сценарий и нажмите «Начать». Отправляйте сообщения и нажимайте кнопки в чате. Панель рядом управляет подпиской, пользователями и подтверждением розыгрыша. Стенд использует MAX-эмулятор, настоящий HTTP-клиент сервиса и отдельную PostgreSQL.

Сценарий «Участие в акции» подходит для промокодов и подписки, «Дневной розыгрыш» для получения приза, «Финальный розыгрыш» для выбора пяти победителей. Остановка: `make simulator-down`. [Устройство стенда](operations.md).

### В Postman

Импортируйте [коллекцию Postman](../postman/promo.postman_collection.json) и [окружение](../postman/local.postman_environment.json), выберите окружение и запустите Collection Runner с начала.

| Папка коллекции | Что проверяет |
| --- | --- |
| Standard participation | Повторный код, подписку и один шанс за день |
| Exhausted promo pool | Участие при пустом пуле кодов |
| Daily draw and prize claim | Подтверждение розыгрыша, имя и согласие |
| Weighted final | Финал с весами по активным дням |
| Reserve promotion | Передачу невостребованного приза резерву |
| Authentication and validation | Авторизацию и отклонение неверных запросов |

Каждый сценарий создаёт отдельную акцию с датами относительно текущего времени. Подписка и отправка MAX подменены; PostgreSQL и бизнес-сценарии настоящие. HTTP-ответ webhook подтверждает приём события, результат появляется асинхронно. Коллекция дожидается сообщений сама.

Логи: `make logs`. Остановка: `make down`, данные сохраняются.
